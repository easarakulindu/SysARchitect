## Reproduction and fix

In the native Linux demo: Lessons / Progress > Next lesson three times (Docker)
> Load example > select Docker Host > Create container twice > Run. Deselect
the host to view the enclosure. The previous runtime-only material rendered as
an opaque blue box and hid the actual contained nodes. Source review identified
the runtime-only transparent URP shader keyword/variant as the build difference.

The real `Resources/WorkloadGlass.mat` asset explicitly retains the transparent
variant, blending and disabled depth writes in builds. WorkloadEnclosure clones
and tints it, excludes the visual shell from picking, and disposes owned materials.
The outline now tints its actual material and reflects owner status/selection.
NodeVisual exposes its existing selection state through a read-only getter.
There is no new graph, simulation or workload ownership system.

The same native mouse workflow was repeated after the fix. Both container models
and their routed packets were visible through the shell. Selecting a contained
model through the shell displayed the actual Container inspector. The paused
capture showed **1,368 sent, 1,353 succeeded, 0 failed, 15 in flight**, conserving
requests. This is a scripted verification run, not a learner study.
